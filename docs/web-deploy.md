# Веб-версия «Мой Доктор»: запуск на сервере

Веб-версия — это папка `web/` (статические файлы) плюс тот же FastAPI-сервис `api/`,
который уже обслуживает iOS-приложение. Бот остаётся как был; оба процесса работают
с одним файлом базы SQLite.

Что нужно от вас (я этого сделать не могу): **домен**, **почтовый ящик для отправки кодов**
и доступ к серверу.

## 1. Секреты в `/opt/my_doctor_bot/.env`

```bash
# обязательный секрет подписи токенов (если уже задан для iOS — оставьте тот же)
API_JWT_SECRET=<python3 -c "import secrets; print(secrets.token_urlsafe(48))">

# почта, с которой уходят коды входа (порт 465 = SSL, иной = STARTTLS)
SMTP_HOST=smtp.example.com
SMTP_PORT=465
SMTP_USER=noreply@your-domain.ru
SMTP_PASSWORD=...
SMTP_FROM=Мой Доктор <noreply@your-domain.ru>

# необязательно
WEB_DAILY_MESSAGE_LIMIT=100   # сообщений ИИ на аккаунт за 24 часа (защита счёта Groq)
```

Не включайте на сервере `WEB_DEV_PRINT_CODES` — он пишет коды входа в лог и нужен только для разработки.

Письма с кодом доходят во «Входящие», только если для домена отправителя настроены SPF и DKIM
(в панели вашего почтового провайдера). Без этого часть писем уйдёт в спам.

## 2. Сервис и HTTPS

```bash
cp /opt/my_doctor_bot/deploy/mydoctor-web.service /etc/systemd/system/
systemctl daemon-reload
systemctl enable --now mydoctor-web
systemctl status mydoctor-web --no-pager

# Caddy (HTTPS): поставьте по инструкции caddyserver.com, затем
cp /opt/my_doctor_bot/deploy/Caddyfile /etc/caddy/Caddyfile   # правим домен внутри
systemctl reload caddy
```

Проверка: `curl -s https://ВАШ-ДОМЕН/health` → `{"status":"ok"}`, а `https://ВАШ-ДОМЕН/` открывает страницу входа.

## 3. Перед публикацией

- Заполните в `web/privacy.html` реквизиты в квадратных скобках (оператор, почта для запросов, даты, срок хранения копий) и покажите текст юристу: сервис обрабатывает данные о здоровье
  и передаёт сообщения поставщику ИИ за пределы РФ (Groq, США). Это требует отдельного согласия (оно есть при входе) и, скорее всего, уведомления Роскомнадзора.
- Сделайте копию базы перед первым запуском: `sqlite3 /opt/my_doctor_bot/doctor_bot.db ".backup '/root/backups/before_web.db'"`.
- При первом старте миграция добавляет столбец `users.web_email`, таблицу `email_login_codes` и два уникальных индекса;
  если в базе есть дубли записей дневника/приёмов, сначала рядом создаётся копия `*.backup_dedupe_*`.

## Ограничения веб-версии (по сравнению с ботом)

- нет напоминаний о приёме: в Telegram их присылает бот, в вебе нужно заходить самому;
- консультация только текстовая (фото и PDF анализов пока только в боте);
- аккаунт веб-версии привязан к почте и **не связан** с аккаунтом в Telegram — данные между ними не переносятся.
